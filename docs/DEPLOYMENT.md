# Развёртывание MVP

## Локальный пилот

Основной способ запуска — `bash scripts/start-demo.sh` из корня проекта. Compose-проект `pir-control` изолирован от разработческого `pir-mvp`. Остановка контейнеров не удаляет volume PostgreSQL. Команды удаления volumes в сценариях запуска отсутствуют.

Все прикладные данные, включая снимки отчётов, находятся в PostgreSQL. XLSX формируется на запрос и не хранится в публичной файловой директории. В этой версии отдельный файловый volume и S3 не нужны.

## Подготовка сервера / облачной VM

1. Подготовить Linux-хост с Docker Engine и Compose. Собрать образы из lock-файлов и зафиксированных базовых образов.
2. Создать отдельную базу и случайные пароли; настроить `PIR_DB_PASSWORD`, `PIR_SECRET_KEY`, `PIR_ALLOWED_HOSTS`, `PIR_CSRF_ORIGINS`. Значения сохраняются в приватной `.env` на сервере.
3. Подключить доверенный HTTPS reverse proxy. Контейнерный frontend слушает loopback; внешний proxy должен быть на том же хосте либо доступ организуется отдельной приватной сетью.
4. Настроить корректную передачу HTTPS-схемы от доверенного proxy к Django, затем установить `PIR_DEBUG=0`. При secure cookies вход по обычному HTTP работать не должен.
5. Применить миграции единственной командой `docker compose -p pir-control run --rm api python manage.py migrate`.
6. Создать реальные учётные записи и роли отдельной административной процедурой. Учебный seed запрещён при `PIR_DEBUG=0`; демонстрационные пароли не переносятся в производственную базу.
7. Добавить управление пользователями, MFA и общую защиту входа для нескольких процессов. Текущий in-memory счётчик попыток локален worker-процессу.
8. Проверить восстановление резервной копии, доступ каждой роли, фактическую печать в используемом Excel и объём реального портфеля.

Публикация в облаке в рамках сборки MVP не выполнялась. Домены, сертификаты и инфраструктура пользователя не изменялись. Текущий экземпляр доступен только с компьютера, на котором запущен Docker.

## Резервная копия локального пилота

```bash
mkdir -p private/backups
docker compose -p pir-control exec -T db pg_dump -U pir -d pir -Fc > private/backups/pir.dump
```

Файл содержит производственные данные. `private/` исключён из Git. Для производственного запуска копия переносится на отдельное хранилище; сохранение только на диске приложения не защищает от потери хоста.

Восстановление проверяется в **новой пустой тестовой базе**, а не поверх действующего портфеля:

```bash
docker compose -p pir-control exec -T db createdb -U pir pir_restore_check
docker compose -p pir-control exec -T db pg_restore -U pir -d pir_restore_check < private/backups/pir.dump
```

После этого сравниваются количества графиков/версий и читаемость отчётов. Регламент автоматического резервирования и достижение RPO/RTO из TechPlan ещё требуют настройки на выбранной площадке.

## Обновление

Сделать резервную копию, собрать образы, применить миграции и обновить контейнеры:

```bash
docker compose -p pir-control build
docker compose -p pir-control run --rm api python manage.py migrate
docker compose -p pir-control up -d
```

Не запускать одновременно две миграции. Откат образа допустим только при совместимой схеме; изменение схемы не откатывается автоматически остановкой контейнера.
