# ПИР Контроль — MVP 0.1

Работающее веб-приложение для локального пилота: React / TypeScript, собственный Гант на HTML/SVG, Django REST Framework и PostgreSQL. Основано на [PRD](./PRD_ПИР.md) и [TechPlan](./TechPlan.md).

## Открыть приложение

После запуска: **http://localhost:8088**.

| Учебный логин | Роль |
| --- | --- |
| `gip` | Главный инженер проекта: создание, редактирование, отправка, новая редакция |
| `technical` | Технический директор: утверждение или возврат назначенного графика |
| `finance` | Финансовый директор: те же действия при назначении утверждающим |
| `coordinator` | Координация: ввод факта, отчёты, новая версия календаря |
| `director` | Руководитель: просмотр и отчёты |
| `department` | Начальник отдела ИССО: доступные графики, скрыты суммы чужих отделов |

Пароль учебных учётных записей по умолчанию: **`PirDemo2026!`**. Он предназначен только для демонстрационной базы, доступной с этого компьютера. При первой инициализации можно задать другой пароль через `PIR_DEMO_PASSWORD`. Повторное заполнение не меняет существующие данные и пароли.

## Запуск одним сценарием

Требуются Docker Engine/Desktop и Docker Compose. На первом запуске нужен доступ к реестрам контейнеров, npm и PyPI.

```bash
cd /Users/boburbek/Desktop/Graphic
bash scripts/start-demo.sh
```

Сценарий собирает frontend/backend, запускает PostgreSQL, применяет миграции, создаёт учебный портфель и запускает приложение. Порт `8088` привязан к `127.0.0.1`; база не публикует порт наружу. Данные сохраняются в volume `pir-control_pir-db`.

Остановка с сохранением данных:

```bash
bash scripts/stop-demo.sh
```

Повторный запуск уже собранного приложения:

```bash
docker compose -p pir-control up -d
```

## Проверить основной сценарий

1. Войти как `gip`, открыть «Обзор производства» и один из графиков.
2. Открыть «Новый график», выбрать объект или создать новый, выбрать учебную модель либо индивидуальный график.
3. Задать работы, специальности, авторов, суммы, даты и FS/SS/FF-зависимости. Событие передачи создаётся как работа нулевой длительности с получателем и позицией начала/конца дня.
4. Сохранить. Устранить ошибки проверки; сумма работ должна совпадать с бюджетом.
5. Выбрать директора, отправить на утверждение. Выйти и войти его учётной записью; утвердить график.
6. Войти как `coordinator`, нажать на работу, указать дату состояния, фактические даты, процент и причину задержки.
7. В «Отчётах» выбрать дату и при необходимости момент знания, сформировать свод, сохранить снимок или скачать XLSX.
8. Для переноса сроков вернуться под `gip` и создать новую редакцию с причиной. Первоначальный утверждённый план сохраняется.

Демонстрационные графики относятся к осени 2026 года. После этой даты они закономерно отображаются как просроченные при отсутствии новых записей факта.

## Что реализовано

- Сессии пользователей, CSRF и 6 ролей; серверная проверка доступа.
- Объекты, стадия и этап в паспорте графика; несколько графиков на объект.
- Создание собственного графика или применение учебного шаблона.
- Гант с виртуализированными строками, SVG-зависимостями, масштабами, критическим путём и базовым планом.
- Редактор интервалов, событий и зависимостей, перенос полосы с сохранением рабочей длительности.
- Расчёт CPM для FS/SS/FF, лагов, нескольких критических ветвей, нулевых событий и отрицательного резерва относительно срока.
- Ручные версии календаря с исключениями и переносами; календарный снимок в каждой версии плана.
- Согласование назначенным директором, возврат, новые редакции, история. Содержимое отправленных/утверждённых версий защищено также триггером PostgreSQL.
- Факт по работам, проценты, причины, даты состояния и регистрации.
- Свод утверждённых графиков на дату, просрочки, стоимость и число графиков по специальностям, сохранённые снимки отчётов.
- Excel: свод, печатная форма А4, факт/передачи и параметры; шифры сохраняются текстом.
- Предварительная загрузка работ из XLSX в черновик, без автоматического применения.

Подробные границы MVP и отличия от полного TechPlan: [MVP_SCOPE.md](./docs/MVP_SCOPE.md). MVP не обозначается как выполнение всего P0 PRD.

## Импорт работ

Первая строка активного листа XLSX должна содержать ровно:

```text
ID | Работа | Шифр | Отдел | Автор | Начало | Окончание | Сумма
```

`ID` и `Шифр` — текст, даты — даты Excel или `ГГГГ-ММ-ДД`, сумма — число без формул. До 1000 работ и 5 МБ. Импорт сначала показывает предупреждение и заменяет локальный список редактора; данные попадают в БД только после «Сохранить». Зависимости после такого импорта задаются вручную. Печатная выгрузка не является шаблоном импорта.

## Разработка без сборки Docker приложения

Контейнер PostgreSQL для разработки изолирован от основного пилота:

```bash
docker compose -p pir-mvp -f infra/compose.dev.yaml up -d --wait
python3 -m venv .venv
.venv/bin/pip install -r apps/api/requirements.lock.txt
.venv/bin/python apps/api/manage.py migrate
.venv/bin/python apps/api/manage.py seed_demo --password 'PirDemo2026!'
.venv/bin/python apps/api/manage.py runserver 127.0.0.1:8017
```

В другом терминале:

```bash
cd apps/web
npm ci
npm run dev
```

Интерфейс: `http://127.0.0.1:5173`, API: `127.0.0.1:8017`. Проверены локальные Python 3.14 / Node 20.20 и контейнерные Python 3.13 / Node 24. Зависимости зафиксированы в lock-файлах. Для локальной разработки предусмотрен явный `USE_SQLITE=1`, но интеграционные проверки выполнялись с PostgreSQL.

## Проверки

```bash
.venv/bin/python apps/api/manage.py test pir
cd apps/web
npm run build
npm run test:e2e
```

Браузерные тесты требуют установленных Google Chrome и запущенных API/frontend с учебными данными. `PIR_TEST_URL=http://localhost:8088` переключает их на Docker-сборку. Тест рабочего цикла создаёт отдельный график с префиксом `E2E-`; его следует запускать в тестовой базе.

Скриншоты: [обзор](./docs/acceptance/dashboard.png), [Гант](./docs/acceptance/gantt.png), [мобильный экран](./docs/acceptance/mobile.png). Протокол проверки: [verification.md](./docs/acceptance/verification.md).

## Сервер организации или облако

Одинаковые образы запускаются на Linux-сервере или VM в облаке. Подготовка внешнего доступа, секретов, TLS, копирования и оставшихся функций: [DEPLOYMENT.md](./docs/DEPLOYMENT.md). Текущий Compose предназначен для локального пилота; он не публикует приложение в интернете.
